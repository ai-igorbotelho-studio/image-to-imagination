Ready starting points. Tap to copy and fill in the [brackets].

Web or App? Ask “where does the user open this?” Browser / has a URL (site, web app, dashboard) → bundles A–F. Installed from the App Store / Play, uses device features (push, offline, camera, biometrics, in-app purchase) → bundle G · Apps. What to give a briefing — fill in the [brackets]. You don't need everything up front: the Head asks for what's missing before it runs. Always: the target (site/app URL, file/repo path, or just “this repo” if the session is already open on it), the goal, the audience, and constraints (deadline, budget, stack). By type: audit / lean / ship → the link or repo + which browsers/devices matter · modernize / UI / interactive → references & tone (links you like, adjectives) · match look & feel → the image · backend / AI → what it does + data sources + existing auth · content / SEO / metrics → keywords + conversion goal · Apps (G) → platforms (iOS/Android) + native vs cross-platform. Where it lives: has a URL → paste the link · open in Claude Code → say “this repo”, no link needed · a Claude Design canvas → export PNG/PDF into /design.

Check which version is installed

Which version of the transition interactive is installed here? Count the
transition-interactive-*.md files in .claude/agents/ (and check for a leftover
.claude/agents/transition-interactive/ subfolder), and check if transition-interactive-head.md
exists. 33 + head = current; 18 + no head = old; anything else = partial. If it's
not 33, recommend the Update command.

Seeing only 18 agents? The most common cause: a bare git clone lands on the repo's default branch, which may still be an old 18-agent branch — main has the current 33. Always clone or pull from main:

copy 
git clone --depth 1 --branch main https://github.com/ai-igorbotelho-studio/transition-interactive

Other causes of an old snapshot: a fork, a tag, a cached clone, or an install done before an update. Two things fix it: run the Update command above (pulls the current 33 from main and prunes obsolete roles) and open a new session — subagents load at session start, so the same session can keep showing the old count. Quick tell: if transition-interactive-head is in /agents, you're on 33; if not, you're on 18. Permanent fix (repo owner): set main as the repository's default branch so bare clones get 33.

Updating vs. installing: a fresh install refuses to overwrite; an update intentionally replaces the old .claude/ team files and TRANSITION-INTERACTIVE.md (and prunes roles that were renamed or removed) so the repo moves to the current 33-agent structure. It never touches your own code, your CLAUDE.md, or your DECISIONS.md — if your repo uses DECISIONS.md as its own product decision log, the update leaves it intact (upstream's DECISIONS.md is just the team-build diary and isn't needed in your repo). Subagents load at session start, so open a new session (or reopen /agents) after updating.

Why the wiring: Claude Code only auto-loads a file named exactly CLAUDE.md as project instructions. Since the team doc is TRANSITION-INTERACTIVE.md, add one pointer line to the target repo's CLAUDE.md so every new session's Head reads the pipeline and gates automatically.

Claude chats (claude.ai)

Real subagents only exist in Claude Code. In a plain chat you reproduce the Head manually.

  1. Create a Project on claude.ai (or use the custom instructions).
  2. Paste the TRANSITION-INTERACTIVE.md content as the Project's instructions/knowledge.
  3. Ask: "Act as the Head and coordinate the described roles; when I name a role, embody its profile."
  4. Use the Use the transition-interactive-X subagent to… phrases — Claude simulates the role.

Honest limit: no isolated execution, no scope hook and no automatic gates — it's conversational orchestration, not the tool-backed pipeline.

Claude Design

The team audits and specs; you apply on the canvas.

  1. Finalize the design on the canvas.
  2. Export → PNG/PDF of each artboard (or download the .dc.html file).
  3. Open a Claude Code session with the team and drag the files into /design.
  4. Paste the audit briefing (the "Audit a design/site" block above).
  5. The team returns findings + the fix spec in /design and /docs.
  6. Apply the changes back on the canvas (by hand, or re-seeding via the design skill).
